# Бот продажи подписок на закрытые Telegram-каналы

Бот продаёт доступ к 2–5 закрытым каналам. Покупатель выбирает тариф, переводит деньги вам напрямую (на карту, кошелёк и т.п.) и присылает чек. **Вы проверяете поступление денег и нажимаете «✅ Одобрить»**. Только после этого бот выдаёт покупателю персональную ссылку в канал. Когда подписка заканчивается, бот сам удаляет человека из канала.

> ⚠️ **Скриншот чека можно подделать.** Перед нажатием «Одобрить» всегда проверяйте реальное поступление денег в банке или кошельке. Сверяйте сумму, время и код заказа (например `A7K2Q`), который покупатель указывает в комментарии к переводу. Бот предупреждает, если чек уже присылали к другому заказу, но решение всегда принимаете вы.

## 1. Что проверить перед запуском

Здесь нет юридических утверждений, только список вопросов. **Проверьте каждый пункт самостоятельно или у юриста.**

- [ ] **Оферта / условия.** Нужен текст, который покупатель принимает при оплате: что именно он получает, на какой срок, что будет при блокировке канала. *Проверить у юриста.*
- [ ] **Политика возврата.** Когда и как вы возвращаете деньги. В боте возврат только отмечается («💸 Отметить возврат»), сами деньги вы возвращаете вручную.
- [ ] **Налоги и регистрация.** Нужна ли регистрация (самозанятость, ИП и т.п.) и как платить налог с таких поступлений в вашей стране. *Проверить самостоятельно / у юриста или бухгалтера.*
- [ ] **Ограничения на приём переводов.** Правила вашего банка или кошелька для регулярных переводов от физлиц. Возможны вопросы и блокировки. *Проверить у банка.*
- [ ] **Правила Telegram для платного контента.** Прочитайте условия для разработчиков ботов (https://telegram.org/tos/bot-developers) и правила по цифровым товарам. Telegram может требовать оплату цифровых товаров через Telegram Stars в некоторых случаях. *Проверить самостоятельно, правила меняются.*
- [ ] **Персональные данные.** Бот хранит Telegram ID, имя, @username и чеки. Узнайте, нужна ли политика конфиденциальности в вашей стране. *Проверить у юриста.*

## 2. Подготовка: бот, ID, каналы

1. **Создайте бота.** В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя и username. BotFather пришлёт **токен**: длинную строку вида `123456789:AA...`. Это пароль от бота. Никому его не отправляйте, даже в чат поддержки.
2. **Узнайте свой Telegram ID.** Напишите боту [@userinfobot](https://t.me/userinfobot), он пришлёт число, например `123456789`. Это ваш ID админа. Если админов несколько, каждый узнаёт свой.
3. **Каналы.** В каждом закрытом канале: *Управление каналом → Администраторы → Добавить администратора → найдите вашего бота*. Включите права:
   - **«Пригласительные ссылки» / «Добавление подписчиков»** (Invite users via link). Это обязательно: без него бот не создаст ссылки и не одобрит заявки.
   - **«Блокировка пользователей»** (Ban users), если этот пункт есть. Без него бот не сможет удалять людей с закончившейся подпиской. Бот проверит права при добавлении канала и предупредит, если чего-то не хватает.
   > Названия прав в приложении Telegram для каналов и групп отличаются и могут меняться. **Проверьте удаление на тестовом аккаунте** (п. 6.5).
4. **Каналы должны быть приватными.** Не публикуйте постоянную ссылку-приглашение: доступ даёт только бот.

## 3. Запуск на Windows

### 3.1. Установите Python 3.12

1. Откройте https://www.python.org/downloads/ и скачайте **Python 3.12.x** для Windows.
2. При установке **обязательно поставьте галочку «Add python.exe to PATH»** внизу первого окна. Затем нажмите «Install Now».

### 3.2. Настройте и запустите

1. Положите папку с ботом в удобное место, например `C:\Bots\subscription-bot`.
2. Дважды щёлкните **`run.bat`**. В первый раз бот создаст файл `.env` и откроет его в Блокноте.
3. Заполните в `.env` две строки (остальное можно оставить как есть):
   ```
   BOT_TOKEN=123456789:AA...ваш токен...
   ADMIN_IDS=123456789
   ```
   Можно также указать `SUPPORT_CONTACT=@ваш_логин`. Сохраните файл (Ctrl+S) и закройте Блокнот.
4. Снова дважды щёлкните **`run.bat`**. В первый раз он установит нужные библиотеки, на это нужен интернет и 1–2 минуты. Затем появится строка `Bot @имя started`.
5. Откройте своего бота в Telegram и нажмите **/start**. Вам придёт сообщение «🤖 Бот запущен». В меню будет кнопка «🛠 Админ-панель».

Окно `run.bat` должно оставаться открытым: пока оно открыто, бот работает. Если бот упадёт, `run.bat` сам перезапустит его через 15 секунд. Чтобы остановить бота, закройте окно или нажмите Ctrl+C.

Автозапуск при входе в Windows и защита от сна описаны в [разделе 8](#8-ноутбук-сон-автозапуск-проверка-логи-обновление).

## 4. Запуск на macOS

1. Установите Python 3.12 с https://www.python.org/downloads/macos/ (файл `.pkg`, обычная установка).
2. Откройте **Терминал** (Программы → Утилиты → Терминал) и перейдите в папку бота:
   ```bash
   cd ~/Bots/subscription-bot     # ваш путь к папке
   chmod +x run.sh healthcheck.sh scripts/autostart_macos.sh
   ./run.sh
   ```
3. Первый запуск создаст `.env`. Откройте его (`open -e .env`), заполните `BOT_TOKEN` и `ADMIN_IDS`, сохраните и снова выполните `./run.sh`.
4. Нажмите /start в своём боте.

`run.sh` сам перезапускает бота при сбое. Пока бот работает, он не даёт Mac уснуть от бездействия (через `caffeinate`). Остановить бота: Ctrl+C в окне Терминала.

## 5. Запуск через Docker

Docker нужен, только если вы предпочитаете его вместо `run.bat` / `run.sh`. Docker — это программа, которая запускает бота в изолированном «контейнере» и сама перезапускает его после сбоев и перезагрузки.

1. Установите **Docker Desktop**: https://www.docker.com/products/docker-desktop/ (на Windows он попросит включить WSL 2, соглашайтесь и перезагрузитесь).
2. В Docker Desktop: *Settings → General → «Start Docker Desktop when you sign in»*. Включите, чтобы Docker запускался вместе с компьютером.
3. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` и `ADMIN_IDS`.
4. В терминале (на Windows: PowerShell) в папке бота выполните:
   ```bash
   docker compose up -d --build
   ```
5. Проверка и управление:
   ```bash
   docker compose ps                 # статус (healthy = работает)
   docker compose logs -f --tail 100 # логи (Ctrl+C — выйти из просмотра)
   docker compose restart            # перезапуск
   docker compose down               # остановить
   ```

База данных, бэкапы и логи лежат в папках `data/`, `backups/`, `logs/` рядом с ботом, а не внутри контейнера. Поэтому при обновлении они не теряются.

> Не запускайте бота одновременно через `run.bat` и через Docker: два экземпляра мешают друг другу (ошибка `Conflict: terminated by other getUpdates request`).

## 6. Первая настройка в боте

Всё настраивается кнопками: *Главное меню → 🛠 Админ-панель* (или команда `/admin`). Править код не нужно. Порядок такой:

### 6.1. Способы оплаты и реквизиты
*Админ-панель → 💳 Способы оплаты → ➕ Новый способ* → название (например «Карта Сбер»), валюта (`RUB`), реквизиты (номер карты, получатель, инструкция). Для крипты можно сделать отдельный способ, например «USDT TRC20», с валютой `USDT` и адресом кошелька.

### 6.2. Каналы
*Админ-панель → 📢 Каналы → ➕ Добавить канал* → перешлите боту любой пост из канала (или отправьте ID вида `-100…`). Бот проверит, что он администратор и у него есть нужные права. Если нет, напишет, чего не хватает.

### 6.3. Тарифы
*Админ-панель → 📦 Тарифы → ➕ Новый тариф* → название → описание → срок в днях (`30`, `90`, `365` или `0` = навсегда). Затем в карточке тарифа:
- **📢 Каналы** — отметьте каналы, которые открывает тариф. Можно несколько: покупатель получит отдельную ссылку на каждый.
- **💰 Цены** — укажите цену для каждого способа оплаты (в валюте способа). Автоконвертации нет, каждую цену вы вводите сами. Если цены нет, этот способ не показывается для тарифа.
- **⬆️ ⬇️** — порядок тарифов в каталоге; **⏯** — включить/выключить.

Названия можно писать на двух языках: «Премиум / Premium». Тексты кнопок и сообщений бот переводит сам (русский/английский, по языку Telegram пользователя; пользователь может переключить язык кнопкой).

### 6.4. Промокоды (по желанию)
*🎟 Промокоды → ➕ Новый промокод*: код → тип (процент / фиксированная сумма / только бонусные дни) → бонусные дни → срок действия → лимит использований → тарифы → «один раз на пользователя или много». Покупатель вводит код в меню «🎟 Промокод», и он применяется к следующему заказу.

### 6.5. Проверьте всё на тестовом аккаунте
Попросите знакомого (или используйте второй аккаунт) купить самый дешёвый тариф:
1. Он оформляет заказ, нажимает «Я оплатил(а)» и шлёт любую картинку.
2. Вам приходит карточка заказа → «✅ Одобрить».
3. Ему приходит кнопка «Войти в канал» → он отправляет заявку → бот её одобряет.
4. Проверьте удаление: *Подписчики → найдите его → ⛔ Отозвать доступ*. Он должен пропасть из канала. Если не пропал, у бота нет права «Блокировка пользователей».

## 7. Ежедневная работа админа

**Новые чеки.** Каждый админ из `ADMIN_IDS` получает чек и карточку: покупатель, тариф, каналы, **сумма и валюта, способ оплаты, код заказа**, время. Проверьте поступление денег → «✅ Одобрить» или «❌ Отклонить» (с шаблоном причины или своим текстом). Если два админа нажмут одновременно, сработает только первое нажатие, второй увидит «Уже обработано».

**⚠️ «Этот чек уже был использован в заказе #…»** — бот видит тот же файл или тот же номер операции. Это частый признак обмана, проверьте особенно внимательно.

**Напоминания.** Если чек ждёт проверки дольше 3 часов, бот напомнит (не чаще раза в 3 часа, настраивается в `.env`).

**Очередь.** *🧾 Заказы → 🔎 Очередь на проверку* — все неразобранные чеки. Нажмите на заказ, чтобы получить карточку ещё раз.

**Подписчики.** *👥 Подписчики* → @username или ID → карточка: подписки, заказы, кнопки:
- 🎁 **Выдать доступ** — вручную на N дней (0 = навсегда), например другу или в качестве компенсации;
- ⛔ **Отозвать доступ** — удалить из каналов тарифа;
- 💸 **Отметить возврат** — заказ перестаёт учитываться в выручке (деньги вы возвращаете сами);
- 🔗 **Отправить ссылки** — если человек не успел вступить.

**Отчёт сверки (каждый день в 10:00).** Бот пишет, кто сидит в канале без подписки и у кого подписка есть, а в канал он не вошёл. Сам бот никого не удаляет, пока вы не включите `AUTO_REMOVE_UNPAID=true`.

**Сообщение «🤖 Бот запущен».** Приходит при каждом старте. В нём видно, сколько бот был выключен и что он наверстал (истёкшие подписки, напоминания, отложенные заявки). Если такие сообщения приходят неожиданно, значит ноутбук перезагружался или засыпал.

**Другое:** 📊 Статистика (выручка за день/неделю/месяц по способам и валютам, новые/продлившие/ушедшие, промокоды, рефералы), 📣 Рассылка (всем / активным / истёкшим, с предпросмотром), 📤 Экспорт CSV (открывается в Excel), 📜 Журнал действий (кто что одобрил/выдал/отозвал), 💾 Бэкап сейчас.

## 8. Ноутбук: сон, автозапуск, проверка, логи, обновление

Бот работает, **только пока ноутбук включён, не спит и подключён к интернету**. Если ноутбук спал или был выключен, после включения бот сам наверстает пропущенное. Но Telegram хранит необработанные сообщения только **24 часа**: чеки и нажатия старше суток могут потеряться.

### 8.1. Не давать ноутбуку засыпать

**Windows** (пока работает `run.bat`, бот сам просит Windows не засыпать от бездействия, но закрытие крышки всё равно усыпляет):
- *Параметры → Система → Питание (и батарея) → Экран и спящий режим* → «Переводить в спящий режим» при питании от сети: **Никогда**.
- *Панель управления → Оборудование и звук → Электропитание → Действие при закрытии крышки* → при питании от сети: **Действие не требуется**.
- То же самое командами (запустите «Командную строку» от имени администратора):
  ```bat
  powercfg /change standby-timeout-ac 0
  powercfg /change hibernate-timeout-ac 0
  powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0
  powercfg /setactive SCHEME_CURRENT
  ```

**macOS:**
- *Системные настройки → Аккумулятор (или «Экономия энергии») → Параметры* → включите «Предотвращать автоматический переход в режим сна при питании от сети, когда дисплей выключен».
- `run.sh` уже запускает бота через `caffeinate -is` (не даёт уснуть от бездействия). Для Docker выполните в отдельном окне Терминала: `caffeinate -is`.
- **Закрытие крышки на Mac усыпляет компьютер.** Исключение: режим «закрытой крышки» с внешним монитором и питанием. Держите крышку открытой (можно погасить экран).

Держите ноутбук на зарядке. Интернет лучше по кабелю или стабильному Wi-Fi.

### 8.2. Автозапуск после перезагрузки

- **Docker:** включите в Docker Desktop «Start Docker Desktop when you sign in». Контейнер с `restart: unless-stopped` поднимется сам.
- **Windows без Docker:** дважды щёлкните **`autostart_on.bat`**. В папку «Автозагрузка» добавится запуск `run.bat` в свёрнутом окне при входе в Windows. Выключить: `autostart_off.bat`.
  > Автозапуск срабатывает после **входа в учётную запись**. Если на ноутбуке пароль, после перезагрузки бот запустится, только когда вы войдёте. Автоматический вход без пароля настраивается в Windows отдельно: *проверить самостоятельно*, это снижает безопасность.
- **macOS без Docker:** `./scripts/autostart_macos.sh` (выключить: `./scripts/autostart_macos.sh remove`). Это `launchd`: бот стартует при входе и перезапускается, если остановился.

### 8.3. Как проверить, что бот работает

- Нажмите `/start` в боте: он должен ответить меню.
- **Windows:** дважды щёлкните `healthcheck.bat`. **macOS:** `./healthcheck.sh`. `OK: bot is running` — работает, `NOT RUNNING` — нет.
- Docker: `docker compose ps` должен показывать `healthy`.

### 8.4. Логи

Файл **`logs/bot.log`** (ротируется: максимум 5 файлов по 5 МБ). Откройте его Блокнотом или выполните `tail -f logs/bot.log` на macOS. Токен и персональные данные в лог не пишутся. Ошибки выдачи доступа дополнительно приходят админам в Telegram.

### 8.5. Остановка и обновление

- **Остановить:** закрыть окно `run.bat` (Ctrl+C в `run.sh`) или `docker compose down`.
- **Обновить код:** остановите бота → сделайте бэкап (папку `data/`) → замените файлы бота новыми, **не трогая `.env`, `data/`, `backups/`** → запустите снова. `run.bat`/`run.sh` сами доустановят новые библиотеки; миграции базы применятся автоматически. Для Docker: `docker compose up -d --build`.

## 9. Бэкапы и восстановление

- **Автоматически каждый день** (в 04:00, `BACKUP_HOUR`) бот делает безопасную копию базы в `backups/bot-ГГГГММДД-ЧЧММСС.sqlite3`. Копия делается через встроенный механизм SQLite, а не простым копированием файла, поэтому она целая, даже если бот в этот момент пишет в базу. Хранятся последние 14 копий (`BACKUP_KEEP`).
- **По кнопке:** *Админ-панель → 💾 Бэкап сейчас* — бот пришлёт файл вам в Telegram.
- **Отправка админу каждый день:** `BACKUP_SEND_TO_ADMIN=true` в `.env`.

> **Храните копии не только на ноутбуке.** Если ноутбук сломается или его украдут, папка `backups/` пропадёт вместе с ним. Раз в неделю сохраняйте свежую копию в облако (Google Диск, iCloud, Яндекс Диск) или включите `BACKUP_SEND_TO_ADMIN`. Файл `.env` тоже храните в надёжном месте: без токена бот не запустится.

**Как восстановить базу из копии:**
1. Остановите бота.
2. В папке `data/` переименуйте `bot.sqlite3` в `bot.sqlite3.broken`. Удалите файлы `bot.sqlite3-wal` и `bot.sqlite3-shm`, если они есть.
3. Скопируйте нужный файл из `backups/` в `data/` и переименуйте его в `bot.sqlite3`.
4. Запустите бота. Всё, что произошло после времени копии, будет потеряно: сверьте последние оплаты вручную.

## 10. Переезд на VPS / Oracle Always Free

VPS — это арендованный сервер, который работает круглосуточно. Это решает проблему сна и выключения ноутбука. Подойдёт любой сервер с Linux (Ubuntu 22.04/24.04), 1 ГБ RAM достаточно. У Oracle Cloud есть бесплатный тариф «Always Free» (в т.ч. серверы ARM Ampere, бот на них работает). *Текущие условия Always Free проверьте на сайте Oracle.*

**Что переносить:** файл `.env` и папку `data/` (база). Папку `backups/` можно взять для истории. Всё остальное — это код, его можно скопировать заново.

**Порядок:**
1. На сервере установите Docker:
   ```bash
   curl -fsSL https://get.docker.com | sudo sh
   ```
2. Скопируйте папку бота на сервер (например через `scp` или WinSCP), **без** папки `.venv`.
3. **Остановите бота на ноутбуке** и отключите автозапуск (`autostart_off.bat` / `docker compose down`). Два работающих бота с одним токеном конфликтуют.
4. Сразу после остановки скопируйте на сервер **свежую** папку `data/` (или свежий бэкап, переименованный в `data/bot.sqlite3`).
5. На сервере в папке бота:
   ```bash
   sudo chown -R 1000:1000 data backups logs   # права для пользователя внутри контейнера
   sudo docker compose up -d --build
   sudo docker compose logs -f --tail 50
   ```
6. **Проверка:** вам придёт «🤖 Бот запущен»; `/start` отвечает; в админ-панели видны старые заказы и подписчики; `sudo docker compose ps` показывает `healthy`.

Docker на сервере сам запускается после перезагрузки, и контейнер с `restart: unless-stopped` поднимется тоже.

## 11. Типовые ошибки

| Симптом | Причина и решение |
|---|---|
| `Telegram rejected BOT_TOKEN` | Токен в `.env` неверный или с пробелами. Скопируйте его заново у @BotFather. |
| `BOT_TOKEN is empty` / `ADMIN_IDS is empty` | Не заполнен `.env` (или файл называется `.env.txt`; в Windows включите показ расширений файлов). |
| Админу не приходят карточки заказов | Админ не нажал `/start` в боте, или его ID не указан в `ADMIN_IDS`. После правки `.env` перезапустите бота. |
| «Бот не является администратором канала» | Добавьте бота админом канала и включите нужные права (п. 2.3). |
| Покупатель нажал ссылку, но не попал в канал | Ссылка действует 24 часа. Пусть нажмёт «Моя подписка → 🔗 Получить ссылку ещё раз». Заявки людей без активной подписки бот отклоняет. |
| `Conflict: terminated by other getUpdates request` | Запущены два экземпляра бота с одним токеном (например `run.bat` и Docker, или ноутбук и VPS). Оставьте один. |
| Окно `run.bat` сразу закрывается | Откройте «Командную строку», перейдите в папку бота (`cd путь`) и запустите `run.bat`, чтобы увидеть ошибку. Чаще всего не установлен Python или не поставлена галочка «Add to PATH». |
| Даты показываются не в том часовом поясе | Укажите `TIMEZONE` в `.env` (например `Europe/Moscow`, `Asia/Almaty`) и перезапустите. |
| В отчёте сверки «по данным Telegram» больше, чем «известно боту» | Это нормально: Telegram не даёт ботам список всех участников. Админы и люди, вступившие до бота, боту не видны (п. 13). |
| «Не удалось удалить из канала…» | У бота нет права «Блокировка пользователей» в канале. Включите его или удалите людей вручную. |
| VPS: `permission denied` в логах | Выполните `sudo chown -R 1000:1000 data backups logs`. |

## 12. Как устроен бот (архитектура)

**Стек:** Python 3.12, aiogram 3 (long polling, без домена и вебхуков), SQLite в режиме WAL (SQLAlchemy 2 async + aiosqlite), собственный планировщик (раз в минуту, состояние хранится в БД), pydantic-settings.

### Таблицы БД и связи
- `users` — пользователи (Telegram ID, язык, реферальный код, `referred_by` → users, активный промокод, бонусные дни, «заблокировал бота»).
- `channels` — каналы (`chat_id`, название, описание, активен).
- `plans` — тарифы (срок в днях или `NULL` = навсегда, порядок, активен); `plan_channels` — связь тариф ↔ каналы (многие-ко-многим).
- `payment_methods` — способы оплаты (название, реквизиты, валюта, `provider`=manual); `plan_prices` — цена (тариф × способ), в копейках/центах.
- `orders` — заказы (уникальный код, пользователь, тариф, способ, суммы, промокод, бонусные дни, статус, чек: `file_id`/`file_unique_id`/текст, кто и когда проверил, причина отказа, флаг «доступ выдан», попытки, возврат); `order_admin_messages` — где у каждого админа лежит карточка (чтобы обновить её после решения).
- `subscriptions` — подписка пользователя на тариф (уникальна пара user+plan): статус, `expires_at` (`NULL` = навсегда), флаги напоминаний.
- `invite_links` — выданные персональные ссылки; `channel_members` — кто в канале, по данным бота.
- `promo_codes`, `promo_plans`, `promo_usages` — промокоды, их тарифы и использования; `referral_rewards` — выданные реферальные награды.
- `audit_log` — журнал действий админов; `broadcasts` — рассылки; `kv` — служебное состояние (последний бэкап, сверка, heartbeat); `fsm_states` — незаконченные диалоги (переживают перезапуск); `schema_version` — версия схемы для миграций.

### Жизненный цикл заказа
```
awaiting_payment ──«Я оплатил» + чек──► pending_review ──Одобрить──► approved (→ подписка → ссылки)
      │                                     │
      ├──«Отменить заказ»──► cancelled      └──Отклонить──► rejected ──новый чек (в течение 24 ч)──► pending_review
      └──нет чека 24 ч──► expired
```
Переход `pending_review → approved/rejected` — это один атомарный `UPDATE … WHERE status='pending_review'`, поэтому второй клик или второй админ получают «Уже обработано». Статус заказа, подписка, использование промокода и реферальная награда сохраняются **в одной транзакции**. Ссылки выдаются после неё. Если выдача не удалась, заказ остаётся `approved` с флагом «доступ не выдан», планировщик повторяет попытку, а админ получает алерт.

### Жизненный цикл подписки
```
(нет) ──одобрение/ручная выдача──► active ──срок + GRACE_DAYS прошёл──► expired ──продление──► active
                                     └──админ «Отозвать»──► revoked ──продление──► active
```
Продление активной подписки прибавляет дни к **текущей дате окончания**, а не к сегодняшней.

### Поток «покупка → одобрение → доступ»
1. Покупатель выбирает тариф и способ → заказ с кодом и реквизитами.
2. «Я оплатил(а)» → фото/файл/текст → заказ `pending_review` → карточка всем админам (с предупреждением о дубле чека).
3. Админ «Одобрить» → транзакция (заказ + подписка + промокод + реферал) → карточки у всех админов обновляются.
4. Бот создаёт для каждого канала персональную ссылку с **заявкой на вступление** (`creates_join_request=True`, срок 24 ч).
5. Покупатель отправляет заявку → бот одобряет её **только если у этого пользователя есть активная подписка на этот канал**. Если ссылку переслали другому человеку, его заявка будет отклонена.

### Поток «окончание → удаление»
За 3 и за 1 день — напоминание с кнопкой «Продлить». После окончания (+ `GRACE_DAYS`) подписка становится `expired`. Бот удаляет человека из каналов тарифа (`ban` + `unban`, чтобы он мог вернуться после оплаты), но не из тех, которые открыты другой его активной подпиской. Затем отправляет уведомление с кнопкой «Оформить заново». Админов и `WHITELIST_IDS` бот не удаляет никогда.

### Наверстывание после простоя
При старте бот: (1) помечает прерванные рассылки; (2) одобряет «зависшие» заявки на вступление подписчиков (если бот был выключен дольше суток, Telegram уже не присылает их как события); (3) прогоняет все задачи планировщика: истёкшие заказы и подписки, напоминания, повтор выдачи доступа, пропущенные бэкап и сверку. Защита от лавины напоминаний: напоминание отправляется, только если оно ещё актуально. Если окно «за 3 дня» уже прошло, придёт только «за 1 день». Уведомления о старых истёкших заказах (старше 6 часов) не отправляются. Флаги напоминаний привязаны к дате окончания, поэтому дублей не бывает. Затем бот читает накопившиеся у Telegram события (до 24 ч) и присылает админам «🤖 Бот запущен, пропущенных событий: N».

## 13. Ограничения

- **Оплата проверяется вручную.** Бот не видит ваш банк. Подтверждение оплаты — ваша ответственность.
- **Нет автопродления.** Бот только напоминает, продление делает сам покупатель.
- **Бот работает, пока включён ноутбук.** Во время сна и выключения он не отвечает. События старше 24 ч Telegram не хранит. Для круглосуточной работы переезжайте на VPS (п. 10).
- **Сверка видит не всех.** В Bot API нет метода, который выдаёт список всех участников канала. Бот проверяет только известных ему людей: подписчиков и тех, кто вступал через бота или попал в обновления участников.
- **Права бота в каналах** (особенно удаление участников) нужно проверить на реальном канале (п. 6.5).
- **Рассылка** прерывается, если бот перезапустить посередине (вы получите отметку в сообщении о старте). Лимит Telegram — около 30 сообщений в секунду, по умолчанию бот шлёт 20.
- **Размер чека** — до 10 МБ (настраивается до 20 МБ, это лимит Telegram на скачивание файлов ботом).

## 14. Для разработчика

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt     # macOS/Linux: .venv/bin/pip
.venv/Scripts/python -m pytest -q                    # тесты (≈1 мин)
.venv/Scripts/python -m bot.main                     # запуск
```

Структура: `bot/handlers` (пользователь, заказы, проверка заказов, события каналов, `admin/*`), `bot/services` (заказы, подписки, доступ, промокоды, рефералы, уведомления, рассылка, бэкап, статистика), `bot/scheduler` (задачи и цикл), `bot/payments` (интерфейс `PaymentMethod`, сейчас только `manual`), `bot/i18n` (все тексты: `ru.py`, `en.py`), `bot/db` (модели, миграции, FSM-хранилище).

- **Миграции:** добавьте функцию в конец списка `MIGRATIONS` в `bot/db/migrations.py`. Она выполнится один раз при старте. Уже выполненные миграции не меняйте.
- **Новый платёжный провайдер** (ЮKassa, Stripe, CryptoBot, Stars): реализуйте `PaymentMethod` в `bot/payments/`, зарегистрируйте в `registry.py`. После подтверждения оплаты вызовите `services.orders.approve_order()` (с `admin_id=None`) и `handlers.review.after_approve()`. Ядро заказов и подписок менять не нужно.
- **Тексты:** только в `bot/i18n/ru.py` и `en.py`. Тест `test_i18n_same_keys_and_placeholders` проверяет, что ключи и плейсхолдеры совпадают.
- Тесты покрывают: расчёт сроков и продление до окончания, идемпотентность и одновременное одобрение, промокоды, рефералы (самореферал, циклы, награда один раз), напоминания и наверстывание после простоя, заявки на вступление (включая пересланную ссылку), бэкап, а также сквозные сценарии через настоящий диспетчер aiogram с имитацией Telegram API.
